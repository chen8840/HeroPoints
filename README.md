# HeroXP 积分乐园

面向一个孩子和多位家长的家庭积分 PWA：按天打分的奖惩日历、积分兑换与撤销、月／年统计、规则与类别管理、多设备云端同步。可在 iPhone（Safari）与 Android（Chrome）上使用，支持添加到主屏幕、离线使用。

- 纯静态站点，发布在 GitHub Pages，无需 Mac 或原生应用构建。
- 业务数据保存在浏览器 `localStorage`，可离线打分；配置 JSONBin.io 后支持多设备同步。
- 运行时零外部依赖：Tailwind CSS 在构建阶段编译为本地文件，不请求任何 CDN。

## 目录结构

```
index.html                  应用入口（页面骨架）
src/app.js                  启动与装配（store / sync / UI）
src/lib/                    日期、DOM、弹层与轻提示
src/domain/                 业务模型、规则版本、统计、三方合并、操作
src/storage/store.js        localStorage 持久化（schema 版本、凭据分离、旧数据迁移）
src/sync/                   JSONBin 客户端、同步编排、备份导入导出
src/ui/                     页面模块（日历、抽屉、商城、统计、规则、弹窗、冲突、安装）
src/data/defaults.json      从《家庭积分奖惩规则表.xlsx》整理的初始化数据（唯一手工维护源）
src/data/defaults.js        由 defaults.json 生成，供浏览器直接导入
public/                     manifest、图标、Service Worker 模板
scripts/                    构建 / 预览 / 检查 / defaults 生成脚本
tests/                      node:test 单元测试
```

## 本地开发

```bash
npm install
npm run dev      # 实时开发 http://localhost:5173/，修改后自动刷新／更新样式
npm run serve    # 预览已有 dist/ http://localhost:4173/（不监听修改）
npm test         # 运行单元测试
npm run build    # 产出 dist/（含本地 Tailwind CSS 与注入版本的 sw.js）
npm run check    # 校验产物：无 CDN 引用、相对路径完整、无凭据打包
```

开发模式直接读取源码，监听 HTML／JavaScript 变化并自动刷新；Tailwind 监听样式与类名变化并生成 `dev-assets/app.css`，浏览器自动更新样式。修改 `src/data/defaults.json` 时自动生成 `defaults.js`。默认端口为5173，已被占用时自动选择下一端口，也可通过 `PORT` 指定。

开发模式不注册 Service Worker，清理当前开发地址的旧注册及 HeroXP 缓存，避免缓存挡住改动；本地业务数据不会清除。离线安装和缓存更新请用 `npm run build && npm run serve` 验证。

生产模式修改 `src/data/defaults.json` 后运行 `node scripts/gen-defaults.mjs`（`npm run build` 会自动执行），`npm run check` 会校验两者一致。

## 部署到 GitHub Pages

1. 推送到 `main` 分支，或手动触发 `Deploy HeroXP to GitHub Pages` 工作流。
2. 仓库 Settings → Pages → Source 选择 **GitHub Actions**。
3. 工作流会依次执行测试、构建、产物检查，然后发布 `dist/`。

站点使用全部相对路径，适配 `https://<用户名>.github.io/<仓库名>/` 子路径部署，并包含 `.nojekyll`。

## 手机安装

- **iPhone / iPad（Safari）**：打开站点 → 分享按钮 → 「添加到主屏幕」。之后从主屏幕启动即为独立窗口，离线可用。
- **Android（Chrome）**：打开站点 → 菜单中选择「安装应用」或「添加到主屏幕」；页面内“规则类别”页也会在浏览器支持时提供“安装到手机桌面”按钮。
- 首次必须联网打开一次以下载缓存；之后可离线打分、改规则、兑换与查看统计。

## 配置 JSONBin 云端同步（可选）

1. 注册 [jsonbin.io](https://jsonbin.io)（免费额度足够家庭使用）。
2. 新建一个 Bin。**JSONBin 不允许 Bin 内容为空**，随便填点占位内容（例如 `{"a":"a"}`）即可；应用不会自动覆盖无法识别的内容。
3. 在 jsonbin.io 的 API Keys 页面复制 Master Key（或对该 Bin 有读写权限的 Access Key）。
4. 在应用内「规则类别」页 → 「配置云端接口」，填入 Bin ID 与密钥，点顶部「同步」。
5. 首次同步会提示“云端内容不是 HeroXP 数据”，确认后用本机数据初始化云端；之后其他家长设备填写**同一个 Bin ID 与密钥**即可共享数据。

注意：

- Bin ID 与密钥只保存在本设备的浏览器存储中，不会进入源码、仓库、部署产物，也不会出现在导出备份里。但能访问本机浏览器数据的他人可能读取到密钥，请勿在公用设备上填写。
- 同步策略：每次打开应用时若当天尚未成功检查过，会自动读取云端并合并；打分等操作只写本机，当天成功检查后的新修改会在次日首次打开时自动同步，或随时点「同步」立即上传。手动同步每天最多 3 次（自动检查不占用手动次数，达到上限会提示，次日恢复）。
- 冲突处理：同一内容在多台设备被改成不同值时，应用会逐条弹出选择（保留本机或云端），确认前不会写入云端，也不会标记当天检查成功。

## 数据与备份

- 所有数据先写入本机；浏览器站点数据可能被系统清理，请在「规则类别」页定期「导出数据备份」保存 JSON 文件。
- 「导入恢复数据」按稳定 ID 合并：重复导入不会重复计分，导入内容会标记为待同步，可通过手动同步上传云端。
- 应用内置从旧版原型（`localStorage` 键 `HERO_XP_DATA`）的一次性数据迁移，迁移不会删除原始数据。

## 规则分值的生效方式

- 每个事项只有一个当前分值；修改分值会生成带生效日期的新版本。
- 记分日期早于修改日期的历史记录仍按旧分值计算；修改当天及以后按新分值计算。
- 删除事项／类别／兑换方案均为软删除：不再出现在打分面板，但历史得分与兑换记录保持有效。
- 兑换记录引用当时的方案版本，之后调整积分档不影响已兑换记录的消耗值。
- 「每天跳绳200个」（3 分）与「每天跳绳300个」（5 分）是两个独立事项，同一天都完成可累计 8 分。
- 兑换周期（每周日／每月等）只作为说明展示，应用不做强制限制，由家长自行判断。
- 类别与事项支持上下移动排序（「规则类别」页每行的 ↑↓ 按钮）：只调整被移动项的序号，两端各自的排序修改可以自动合并，不会互相覆盖。

## 已知限制

- JSONBin 为整文档读改写，应用在写回前会复查远端是否被其他设备修改，检测到变化即中止本次写入；但不能绝对排除两台设备同时同步造成的竞争，界面不承诺强一致。
- iOS/Android 均不保证应用被系统终止后执行后台任务；同步只发生在打开应用或手动点击时。
- 主屏幕安装、离线冷启动、软键盘与横竖屏表现建议分别在 iPhone 与 Android 实机验收。
